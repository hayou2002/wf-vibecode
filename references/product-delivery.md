# 从零开发与真实交付

只在 T2 或涉及数据、权限、外部服务的任务使用。T0/T1 不强制建立这些文件；能从现有项目读取的规则不重复创建。

## 先写可测规格

一页以内说清：目标用户、核心任务、真实内容、非目标，以及 3–5 条「给什么输入 → 看到什么结果」的验收句。外部事实、用户偏好和技术假设分开；规格未确认时不铺开多功能开发。

技术选型优先复用项目、官方脚手架和开发参考库中的现成能力。重要取舍在 `docs/adr/` 留短记录：候选、选择理由、费用与退出成本；没有长期价值的小选择不写 ADR。

## 可运行骨架

- 用官方脚手架或项目现有模板；锁定依赖，保留启动、检查和环境说明。
- 建立 Git 与目录边界；有 Git 就用 Git 回退，无 Git 先留快照。
- 准备 `.env.example`，只写变量名和用途，不写真实值。
- 开发、预览、生产环境分别记录变量来源、数据归属和允许动作。
- 不把密钥写入源码、日志、任务文件、参考库或对话。

## 数据、契约与权限

- 先确定真实数据来源、表/字段/关系、唯一约束、迁移顺序和回滚方式，再铺开界面。
- 数据库变更先读现有结构与数据量；禁止用删数据换取测试通过。使用 Postgres/Supabase 时查官方对应 Skill 与当前文档。
- 接口先约定输入、输出、错误和权限，再让前后端按同一契约实现。
- 涉及登录或多人数据时列权限矩阵：资源 × 角色的读取、新建、修改、删除，以及由哪条服务端策略保证。
- 付费内容、隐私数据和权限校验必须在服务端执行，不能仅靠前端隐藏。

## 第一条真实垂直切片

选择最能暴露风险的一条链路，例如「登录 → 写入 → 数据库持久化 → 页面回读」。它必须穿过实际需要的界面、接口、数据和权限，不用假数据冒充集成。

设计方向或页面契约由 `wf-design` 负责；业务逻辑、数据和真实集成本工作流负责。样板只验证方向，不能作为复杂产品已经可交付的证据。

后续按可独立验收的纵向切片推进。每片完成就跑关联检查、审查风险和保存回退点；跨片问题先回到方案，不堆到最后。

## 上线前的真实验收

- 主流程、空/加载/错误状态、目标视口和真实浏览器路径。
- 数据库读写、权限拒绝、服务端数据边界与迁移回滚。
- 构建、密钥扫描、日志和关键错误的定位方式。
- 需要外部服务时区分 mock、测试环境和真实生产验证。
- 用户明确选择平台后，才按其官方 CLI/MCP/Skill 配置预览；记录版本、配置和回滚入口。
- 上线后回读真实行为并确认回滚路径可用。未获部署授权时只交付本地结果与配置清单。

## 进度与证据

长期项目在 `projects/<项目>/work/progress/` 记录计划、任务、进度、决策和审查；启用小队时按 `wf-agent-team` 的角色与文件归属补充。主控依据实际 diff、测试、浏览器和远端回读判断完成，不以子 Agent 汇报代替验收。
